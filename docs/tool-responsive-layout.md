# Tool Responsive Layout

## 适用范围

本文档定义首页、`/weather-map`、`/city-finder`、`/zh/weather-map` 和 `/zh/city-finder` 的顶部导航，以及两个工具 Tab 的响应式布局规则。它是顶部导航和工具页响应式行为的验收规范，不替代具体 CSS 实现。

## 实现归属

| 对象 | 真源 | 说明 |
| --- | --- | --- |
| 顶部导航 HTML | `apps/web/src/components/SiteNav.astro` | 静态 Astro 组件，首页和工具页共用 |
| 顶部导航样式 | `apps/web/src/styles/global.css` | `.site-nav`、`.brand`、`.tabs`、`.nav-actions`、`.nav-icon-btn` 和 `--nav-*` 变量都在这里 |
| City Finder 外壳 | `apps/web/src/pages/[locale]/city-finder.astro` | `SiteNav` 在 React island 外面，页面内容由 `CityFinderToolPage.astro` 接入 |
| Weather Map 外壳 | `apps/web/src/pages/[locale]/weather-map.astro` | `SiteNav` 在 React island 外面，页面内容由 `WeatherMapToolPage.astro` 接入 |
| Landing 外壳 | `apps/web/src/pages/[locale].astro` | 复用同一个 `SiteNav`，页面专属样式只负责 hero 和 Landing 内容 |
| City Finder 工作区 | `apps/web/src/components/weather-dashboard/CityFinderDashboard.tsx` | 负责城市查找页的筛选、城市列表、十四天预报、地图和 URL 状态同步 |
| Weather Map 工作区 | `apps/web/src/components/weather-dashboard/WeatherMapDashboard.tsx` | 负责天气地图页的地区、日期、图层、排序、地图数据和 URL 状态同步 |
| 筛选控件 | `apps/web/src/components/weather-filter-docks/CityFinderFilterDock.tsx`、`apps/web/src/components/weather-filter-docks/WeatherMapFilterDock.tsx` | 两个工具页各自拥有筛选入口，只复用稳定的小控件和类型 |

页面专属 CSS 不覆盖顶部导航的字号、位置、断点、Tab 尺寸、颜色变量和按钮尺寸。需要改顶部导航时，只改 `SiteNav.astro` 和 `global.css` 里的共享导航样式。

## 静态化边界

顶部导航本身是静态 HTML，不能做成 React 组件，也不能放进工具页 React island 里。原因是首页和工具页都需要尽量保持静态输出，方便 SEO、首屏性能和缓存。

工具页允许 React 在 hydration 后增强静态导航里的链接，例如把语言切换链接同步成当前筛选条件对应的 URL，或把工具 Tab 链接同步成上次保存的 query。这个增强只更新已有 `<a>` 的 `href` 和 active class，不重新渲染导航结构。

```text
工具页 DOM 顺序
┌────────────────────────────────────────────┐
│ SiteNav.astro 静态 HTML                    │
├────────────────────────────────────────────┤
│ CityFinderDashboard 或 WeatherMapDashboard │
│ 各自的筛选 / 城市 / 天气 / 地图 / URL 同步  │
└────────────────────────────────────────────┘
```

## 断点

| 范围 | 顶部导航 | 工具页主体 | 页面滚动 |
| --- | --- | --- | --- |
| 宽屏 `> 1120px` | 品牌、Tab、按钮同一行 | 三列：左城市，中天气，右地图 | 工具页高度等于视口，页面本身不滚动 |
| 中屏 `<= 1120px` | 仍保持同一行，直到进入小屏断点 | 第一行城市和天气两列，地图第二行全宽 | 页面允许上下滚动 |
| 小屏 `<= 760px` | 品牌和按钮第一行，Tab 换行到第二行并独占这一行 | 城市、天气、地图全单列 | 页面允许上下滚动 |

只有宽屏三列布局和屏幕一样高。中屏和小屏都不强行同屏铺满，页面可以上下滚动，长内容由各自面板内部滚动或自然展开处理。

Landing hero 还有自己的页面内容断点，目前在 `landing.css` 使用 `1100px` 和 `620px`。这些断点只服务 Landing hero，不影响顶部导航；顶部导航的小屏断点统一以 `global.css` 的 `760px` 为准。

## 顶部导航

顶部导航在首页和两个工具页保持同一套结构：左侧品牌，中间工具 Tab，右侧温度和语言按钮。宽屏和中屏是三块同一行；进入小屏后，Tab 从第一行换到第二行。

宽屏和中屏同一行：

```text
┌──────────────────────────────────────────────────────────────┐
│ Weather Trip       [ Home | Weather map | City finder ]   °C ◎│
└──────────────────────────────────────────────────────────────┘

grid:
┌──────────────┬──────────────────────────────┬───────────────┐
│ brand        │ tabs                         │ actions       │
└──────────────┴──────────────────────────────┴───────────────┘
```

小屏换成两行，Tab 独占第二行：

```text
┌──────────────────────────┐
│ Weather Trip        °C ◎ │
│ [ Home | Map | Finder ]  │
└──────────────────────────┘

grid:
┌──────────────────┬───────┐
│ brand            │actions│
├──────────────────┴───────┤
│ tabs                     │
└──────────────────────────┘
```

小屏第二行的 Tab 是内容宽度，不是全屏宽度：

```text
正确：
┌──────────────────────────┐
│ Weather Trip        °C ◎ │
│      [ Home Map City ]   │
└──────────────────────────┘

错误：
┌──────────────────────────┐
│ Weather Trip        °C ◎ │
│ Home  | Weather | City   │
│ <------- 全宽拉伸 ------> │
└──────────────────────────┘
```

规则：

| 对象 | 规则 |
| --- | --- |
| 品牌 | 第一行左侧，单行显示，小屏字号由共享 CSS 统一降到 `15px` |
| Tab 容器 | 小屏必须从第一行换到第二行，独占一整行，居中，宽度按内容收缩，最大不超过屏幕 |
| Tab 链接 | 文字垂直居中，单行显示，不拉伸到全宽 |
| 右侧按钮 | 第一行右侧，温度单位和语言切换保持同一按钮组 |
| 横向空间不足 | Tab 容器内部横向滚动，不能撑出页面级横向滚动 |

## 筛选区

筛选区在宽屏优先单行排布，中屏和小屏允许自然换行，不用横向滚动条承载整条筛选栏。

### City Finder

`City Finder` 的筛选卡按可用宽度自然换行。`Suggested:` 和后面的快捷项属于同一个可换行组件，`Suggested:` 使用更弱的文字颜色，并通过 CSS 追加冒号。它不作为固定左侧标签占位，后续快捷项和它一起在同一个换行流里排列。

```text
┌──────────────────────────────────────────────────────────────┐
│ Region │ Province │ Time │ Weather │ Temperature │ ...       │
│ Suggested: Comfortable sun  Dry weather  Mild temperature ... │
└──────────────────────────────────────────────────────────────┘
```

行间距保持紧凑，推荐行的 `row-gap` 目前是 `2px`。推荐内容可以占全宽；小屏和中屏都允许推荐项自由换行。

### Weather Map

`Weather Map` 的筛选卡在中屏和小屏保持固定结构：

| 行 | 内容 | 规则 |
| --- | --- | --- |
| 第一行 | `Region`、`Province`、`Date` | 三者等宽横向排布 |
| 第二行 | `Layer` | 独占全宽 |

`Layer` 独占全宽后，内部图层按钮按可用宽度自然换行。宽屏可保持一行 7 个按钮；中屏和小屏都允许换行。

中屏和小屏：

```text
┌──────────────┬──────────────┬──────────────┐
│ Region       │ Province     │ Date         │
├──────────────┴──────────────┴──────────────┤
│ Layer                                      │
│ Weather Temperature Humidity Rainfall ...  │
└────────────────────────────────────────────┘
```

窄手机：

```text
┌────────┬────────┬────────┐
│ Region │Province│ Date   │
├────────┴────────┴────────┤
│ Layer                    │
│ Weather Temp RH Rainfall │
│ Wind Elevation Comfort   │
└──────────────────────────┘
```

## 城市列表

城市列表上方的三个统计项始终横向三列排布，小屏不改成纵向堆叠。

城市结果行始终单行展示，不因屏幕变窄改成上下两行。城市卡片需要有足够宽度；如果空间不足，只允许低优先级字段省略，不能把页面撑出横向滚动。

| 列 | 内容 | 宽度规则 |
| --- | --- | --- |
| 1 | 城市名 | 靠左，尽可能完整显示，过长省略 |
| 2 | 国家/地区信息 | 靠左，占剩余弹性空间，能显示多少算多少 |
| 3 | 次要天气信息 | 靠左，尽可能完整显示 |
| 4 | 主指标 | 靠右，尽可能完整显示 |

```text
┌────────────────────────────────────────────┐
│ 覆盖区域       城市样本       高匹配城市    │
├────────────────────────────────────────────┤
│ 城市名  国家/地区剩余空间...  次要信息  主指标 │
│ 城市名  国家/地区剩余空间...  次要信息  主指标 │
└────────────────────────────────────────────┘
```

国家/地区信息必须靠左。布局优先保证最左城市名和最右详细信息尽可能显示完整，中间国家/地区信息占剩余空间。

## 滚动责任

| 场景 | 滚动归属 |
| --- | --- |
| 宽屏工具页 | 页面不滚动，城市列表、天气预报等内部区域滚动 |
| 中屏工具页 | 页面可上下滚动，城市列表和天气预报有最大高度并内部滚动 |
| 小屏工具页 | 页面可上下滚动，城市列表和地图限高；天气预报自然展开成两列 |
| 筛选弹层 | 弹层内容超过高度时自己滚动 |
| 顶部 Tab | 空间不足时 Tab 容器内部横向滚动，不能产生页面级横向滚动 |

## 禁止项

| 禁止项 | 原因 |
| --- | --- |
| 在 `landing.css` 里覆盖 `.site-nav`、`.brand`、`.tabs`、`.nav-actions` | 会让首页导航和工具页导航分叉 |
| 把顶部导航做成 React 组件 | 导航是静态骨架，应服务 SEO 和首屏性能 |
| 在小屏把 Tab 拉伸成全宽三等分 | Tab 应按内容收缩并居中 |
| 让城市行换成两行 | 城市列表需要稳定的横向扫描节奏 |
| 用页面级横向滚动解决窄屏问题 | 会破坏移动端体验和可访问性 |

## 验证要求

调整顶部导航或工具页响应式布局后，至少检查以下视口：

| 视口 | 需要确认 |
| --- | --- |
| `1440px` | 工具页三列布局，页面不纵向滚动，城市/天气/地图同高 |
| `900px` | 城市和天气在第一行，地图在第二行，页面可纵向滚动 |
| `390px` | 顶部 Tab 在第二行居中，工具页单列，天气预报两列，`Weather Map` 筛选第一行三等分、`Layer` 全宽 |

每个视口都要确认：

```js
document.documentElement.scrollWidth <= document.documentElement.clientWidth
```

导航还要额外确认：

| 检查项 | 标准 |
| --- | --- |
| 静态输出 | 首页 HTML 不包含 `astro-island` |
| 工具页边界 | `.site-nav` 内没有 `astro-island`，导航在工具页 React island 之前 |
| 三页一致 | `/`、`/city-finder`、`/weather-map` 在同一视口下 Tab 宽度、品牌字号、按钮位置一致 |
| 垂直居中 | `.tabs a` 使用 `inline-flex` / `flex`，`align-items: center`，`justify-content: center` |
